# Этап 6. Формирование приказов

## Что сделано

PR закрывает этап 6 плана разработки ИС КЭДО:
автоматическое и пакетное формирование приказов из согласованных заявлений.

Соответствие расчётно-пояснительной записке:
FR090, FR100, UC080.

## Реализованные сценарии

### Формирование приказа из заявления

- в реестре документов добавлен раздел «Формирование приказов»;
- раздел показывает согласованные и подписанные заявления,
  для которых приказ ещё не создан;
- из карточки заявления доступно действие
  «Сформировать проект приказа»;
- приказ создаётся как черновик и получает ссылку `baseDoc`
  на исходное заявление;
- в реквизиты приказа переносятся основание, период отпуска,
  комментарий, ФИО автора, подразделение, должность и табельный номер;
- повторное формирование приказа по одному и тому же заявлению запрещено;
- создание приказа фиксируется в журнале аудита.

### Пакетное формирование

- поддерживается загрузка файлов CSV, XLSX и XLS;
- обязательный столбец файла — `ID заявления`;
- названия столбцов распознаются в русском и латинском вариантах;
- каждая строка обрабатывается в отдельной транзакции;
- строка создаёт документ только после проверки вида,
  статуса и наличия согласованного заявления;
- некорректная строка не откатывает документы,
  созданные из остальных строк;
- интерфейс показывает общее число строк,
  число успешных строк и построчный отчёт с причинами ошибок.

### Маршрут пакетного подписание

- при загрузке доступна опция «Сразу отправить по маршруту»;
- сформированные документы отправляются через существующий
  `RoutingService`, а не через отдельную бизнес-ветку;
- этап действия `SIGN` завершает маршрут в статусе `SIGNED`;
- данные исполнителя и времени фиксируются в данных этапа,
  решение попадает в журнал аудита как подписание.

## Интерфейс

- на странице документов добавлена ссылка на раздел формирования приказов;
- карточка согласованного заявления содержит кнопку однократного формирования;
- карточка приказа показывает документ-основание;
- страница пакетной загрузки показывает доступные заявления,
  форму загрузки и отчёт построчно.

## Проверка

- модульные тесты покрывают перенос полей в приказ,
  отклонение несогласованного заявления и смешанный пакетный файл;
- тесты запускаются вместе со всей модульной частью проекта;
- `./gradlew.bat test --no-daemon` проходит.
